# detail: idiom review

Reviewed version: 0.1.0

The review items of docs/TD_IDIOMS.md, checked by hand for this version: tick each box
(`- [x]`) and say in a few words how it holds.

- [x] P4 Pulse for actions, Toggle for states, Menu for discrete choices; labels in Title Case. Names of 10 characters or fewer are checked at save time (assert_idiomatic); TouchDesigner itself refuses names that aren't an uppercase letter followed by lowercase letters or digits. [Custom Parameters](https://docs.derivative.ca/Custom_Parameters), [Page Class](https://docs.derivative.ca/Page_Class)
  Floats for Detail, Tone, Edge Contrast, Noise Floor, Beat Kick, Loudness, Depth Focus and Max Distance; Menus for Depth Type and Flashing (discrete choices; Flashing the standard one); a Toggle for Full Screen (a state); an Int for Display; Pulses for Open Window and Open Docs. Labels in Title Case (Edge Contrast, Noise Floor, Beat Kick, Depth Focus, Depth Type, Max Distance). Edge Contrast's name is Edge, Noise Floor's Floor; the longest names are Depthfocus and Openwindow (10).
- [x] P5 Inner operators follow the COMP's parameters through expressions (`parent().par.Amount`), not scripts copying values; values only the inside needs are kept off the pages (`ipar`). [Internal Parameters](https://docs.derivative.ca/Internal_Parameters)
  Every inner operator follows the page through expressions: detail_now (a Constant CHOP) is Detail plus Beat Kick times kick_env and Loudness times level_now against level_usual (only while input 2 has a source), clamped; copies_a and copies_b read detail_now, Tone and Edge Contrast as uR; each collapse pass reads Depth Focus (only with input 3 wired) and Noise Floor (only while detail_now is above 0) as uC; near reads Depth Type and Max Distance; the flash gate's spacing follows Flashing (lib flash_gate()). The only script is parexec (Open Window, Open Docs): actions, not copied values. The model's constants (the kick's 2 and 0.3 s, the swell's 4 and its limit of 1, the usual level's 4 s and the smoothing's 1 s, the eight copies' levels, seven pyramid levels) live in the builder, off the page.
- [x] P6 Related parameters are grouped with `startSection`; parameters that don't apply in the current mode are grayed out with `enableExpr`.
  Sections: Detail to Noise Floor (the filter), Beat Kick and Loudness (input 2), Depth Focus to Max Distance (input 3), Flashing, then the window. Max Distance grays out unless Depth Type is Distance in Meters. Noise Floor stays live with Detail below 0, as its help says it only acts while Detail boosts: Detail moves with the music, so graying it by Detail alone would be wrong for a moment on each beat.
- [x] I4 The audio input goes through `audio_in()`, which reads it by channel name with fallbacks and takes a pulse from its count channel when one exists, because a one-frame pulse is lost on any frame nothing pulls the CHOP; the effect reads the counts (`beat_count`, `bar_count`...) for logic, not `beat`. [Cook](https://docs.derivative.ca/Cook), [Logic CHOP](https://docs.derivative.ca/Logic_CHOP)
  Input 2 goes through audio_in(). counts selects beat_count, steps (a time-sliced Slope CHOP) is above 0 on the frame it rises, flash_gate() lets a beat through as often as Flashing allows, and kick_env (a Trigger CHOP) is its jump. The loudness is level_pick (audio's level) smoothed by level_now (a Filter CHOP over 1 s) and judged against level_usual (a box Filter CHOP over 4 s). The one-frame beat channel is never read. With nothing wired, source is 0 and the swell drops out; the kick never fires.
- [x] E2 Only capitalized members are promoted; state lives on `self` and the extension can be reinitialized at any time; no module globals; `onInitTD`/`onDestroyTD`, the 2025 names. [Release Notes 2025](https://docs.derivative.ca/Release_Notes/2025.30000)
  No extension in this effect, so nothing to promote or reinitialize.
- [x] C4 Motion and timing follow seconds (`absTime.seconds`, `me.time.seconds`), not frame counts, so dropped frames don't change the speed. [AbsTime Class](https://docs.derivative.ca/AbsTime_Class)
  The kick's fall is a Trigger CHOP's decay in seconds (0.3), the gate's spacing a Trigger CHOP's re-trigger delay in seconds, the loudness's smoothing a Filter CHOP 1 s wide and its usual level a box Filter CHOP 4 s wide. The picture itself has no state: each frame's result comes from that frame alone.
- [x] C5 Nothing cooks while the output is unused: checked with `dev/idle.py` (nothing downstream, the node out of view; input 2 unwired and wired to a changing beat), or in the Performance Monitor. [Performance Monitor](https://docs.derivative.ca/Performance_Monitor_Dialog)
  dev/idle.py on the final build (node viewer off, nothing downstream): 0 of 310 operators (the Network Boxes' insides included) cooked over 60 frames unused, with input 2 unwired and with the clip, its depth and a beat changing every frame wired in; the control (pulling out_top) cooked 76 and 80. No expression reads another operator's size: the pyramids' levels follow the input through the resolution menu (half), and the shaders read their sizes with textureSize(). detail_now (a Constant CHOP with an expression) cooks only when the copies read it.
- [x] C6 Pixel formats are 8-bit unless precision is needed, and 32-bit float for data textures (a CHOP to TOP feeding a shader).
  collapse0's output takes the input's format (8-bit from a movie). luma, its pyramid (l1 to l7) and collapse1 to collapse6 are 32-bit float mono; copies_a, copies_b and their pyramids (a1 to a7, b1 to b7) 32-bit float RGBA. Each band is a small difference of two levels, interpolated between two copies and summed over seven passes, and with Detail 0 and Tone 1 the picture must come back as it was: it came back exactly (a maximum difference of 0 in 8 bits on three clips). near is lib's 16-bit float at a quarter size. No CHOP-to-TOP data textures.
- [x] C7 The performance note on the docs page was measured on the reference machine at 1280 x 720, not estimated.
  dev/perf.py on the final build, three runs with /tdlib_demo paused (dev/probes/demo_pause.py; MacBook Pro M2 Pro 16 GB, macOS 15.6, TouchDesigner 2025.33230), 1280 x 720, defaults, stress beat: GPU 3.06, 2.85, 2.84 ms (95th percentile 3.97, 3.66, 3.82), CPU 0.79, 0.67, 0.71 ms (0.89, 0.57, 0.72), 60 fps held each time; the page gives the medians, 2.9 ms (3.8) and 0.7 ms. Costliest: collapse0 0.5-0.6 (the full-size pass with nine inputs), collapse1, collapse3 and collapse5 about 0.3 each (the small passes cost more than their size: each binds eight inputs and waits on the pyramids). With a song as raw audio on input 2: CPU 1.03 ms, of which the audio input 0.37, GPU 2.53. The README DAT says about 3 ms.
- [x] D5 The README DAT and docs page say how to update: dragging a `.tox` in embeds a copy, so updating means dragging in the new one (or pointing External .tox at it). [A word about external files](https://derivative.ca/community-post/word-about-external-files-202310k-builds/68166)
  The README DAT's UPDATING section and the docs page's Use it section both say to delete the copy and drag in the new detail.tox, or point External .tox at a downloaded file.
- [x] D6 Provenance: the README DAT's CREDITS and the docs page's Credits and license name every paper, technique, project, code, font, model and media the effect uses, follows or was built after, with links and licenses, and call original only what was designed here and has no earlier source after a search. Code recalled from elsewhere that can't be traced is replaced, never called original; code taken from elsewhere is also credited where it sits (a comment in the shader or script). D3 and check_tox.py only see that the sections exist.
  CREDITS and the docs page name Paris, Hasinoff and Kautz 2011 for the local Laplacian filter (its remapping, curves, brightness-only color and noise smooth step); Aubry, Paris, Hasinoff, Kautz and Durand 2014 for the fast form (copies interpolated, the Gaussian remapping); Rossi 1978 (SMPTE Journal) for coring, which Noise Floor follows; Burt and Adelson 1983 for the Laplacian pyramid (lib pyramid_down.glsl and pyramid.glsl) and their multiresolution spline for Depth Focus's blend; Sigg and Hadwiger 2005 for the B-spline expand; the depth cameras and lib's depth reading; WCAG 2.3.1; and the preview footage (CC BY 4.0, AI-generated). Each shader's header says the same where it sits. Nothing is called original: the eight copies packed four to a texture, coring in the collapse, the beat's jump through the gate and the loudness against its usual level are said to be written for this library. The code was written from the papers' descriptions, not from their authors' Matlab or Halide code. The docs page has a Patents paragraph (search 2026-10-27: nothing on the filter by its authors or their institutions; Adobe's US 8,831,340 and 9,230,312 claim something else; Stewart's US 10,839,487's per-level limiter isn't used) and names Retinex as Not used, on its look.
- [x] A2 The flash limits were measured, not assumed: the output recorded with a beat-heavy input at each Flashing setting, and the flashes in any one second counted.
  dev/flash.py + dev/flashcount.py on the final build's network (the last two builds changed only the README DAT's text and the builder's layout of one expression), one run at a time, each Flashing setting, worst second by the area rule (red where any), Off / Calm / Up to 3 per second (clip alone). Stress beat: dancer 1.0 each (1.0); plaza 0.5/0.5/1.0 (0.5); flowers 1.0 red 1.0 / 1.0 red 1.0 / 1.0 red 1.5 (1.0, red 1.0); koi 1.0 red 1.5 / 1.0 red 1.5 / 1.0 red 2.5 (0.5, red 1.5); face 0.5/1.0/1.0 (0.5); night field 0 (0). Dance beat (140 BPM): dancer 1.0 each; flowers 1.0 red 1.0 / 1.0 red 1.0 / 1.0 red 1.5; koi 1.0 red 1.5 / 1.0 red 1.5 / 1.0 red 2.0; face 0.5/1.0/1.0. A song as raw audio (m1x_ease_from_drop): dancer 1.0 each; flowers 1.0 red 1.0 / 1.0 red 1.0 / 1.5 red 1.5; koi 1.0 red 1.5 / 1.0 red 1.5 / 1.0 red 2.0. No music: dancer 1.0, flowers 1.0 red 1.0, each setting. Corners at 140 BPM, spot-checked 'not crazy' and all within their setting's rule: Detail -1 with Beat Kick 1 (the picture snapping from smooth to crisp) on the flowers 1.0 red 1.0 / 1.0 red 1.5 / 2.5 red 2.0, on the face 0.5/1.0/2.5; Detail 3, Edge Contrast 0.5, Beat Kick 1, Loudness 1 on the flowers 1.0 red 1.0 each, with Tone 2 on the face 1.0 each (clip 0.5). Off measured 1.0 against the clip's 0.5 on the koi and on that last corner: boosted contrast amplifying the clip's own changes, within the count's half-flash margin. Before the Noise Floor moved into the collapse, the same table's first runs (no beat, stress, 140 BPM and a song on the flowers and dancer) measured the same. The beat's jump was +1.5 Detail at Beat Kick 1 at first and showed little in dev/reaction_report.py (beat lift 1.01 against the clip's 0.85 on the dancer), so it is +2; Beat Kick 1 at Up to 3 per second lifted the face's beats to 1.59 against 0.89.
- [x] A3 No meaning rests on hue alone (brightness, size or motion carries it too); the palette is colorblind-safe (orange and blue); text is legible at the size it is shown.
  Nothing is signaled by color: the output is the picture's own colors, its brightness's detail made stronger or weaker and the same change added to every channel. No text in the output.
- [x] A4 Anything unreliable is labeled experimental in its help and docs.
  Nothing of its own is unreliable: the filter is exact at Detail 0, and the beats and loudness come from audio_in(), whose experimental parts (Fosfora's drops, which this effect doesn't read) are labeled on their own pages. No Experimental section is needed.
