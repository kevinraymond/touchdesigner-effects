# marbling: idiom review

Reviewed version: 0.1.0

The review items of docs/TD_IDIOMS.md, checked by hand for this version: tick each box
(`- [x]`) and say in a few words how it holds.

- [x] P4 Pulse for actions, Toggle for states, Menu for discrete choices; labels in Title Case. Names of 10 characters or fewer are checked at save time (assert_idiomatic); TouchDesigner itself refuses names that aren't an uppercase letter followed by lowercase letters or digits. [Custom Parameters](https://docs.derivative.ca/Custom_Parameters), [Page Class](https://docs.derivative.ca/Page_Class)
  Menus for Inks, Pattern, Input 3 Holds, Depth Type and Drops (discrete choices); Floats for Drop Size, Comb, Tine Spacing, Hold, Relax, Sensitivity, Max Distance and Loudness; Toggles for Keep Subject and Full Screen (states); Pulses for Reset, Open Window and Open Docs; an Int for Display. Labels in Title Case (Input 3 Holds keeps its small word lower case). The longest names are Openwindow, Fullscreen, Dropevery and Depthtype (10 or fewer; the save check passes).
- [x] P5 Inner operators follow the COMP's parameters through expressions (`parent().par.Amount`), not scripts copying values; values only the inside needs are kept off the pages (`ipar`). [Internal Parameters](https://docs.derivative.ca/Internal_Parameters)
  Inner operators follow the page through expressions: marble reads Drop Size and Comb (uM, live, so dragging them changes the whole tray), Inks and Keep Subject (only while input 3 is wired); find reads Input 3 Holds and Sensitivity, near Depth Type and Max Distance. tray (a Script CHOP) reads Pattern, Drops, Loudness, Tine Spacing, Hold and Relax as it makes each tool; that is the effect's logic, not a copy of values. The Parameter Execute DAT reset only stores a new count in tray's storage on Reset. Values only the inside needs (64 tools, a drop's largest radius, a comb's largest pull, the tines' sharpness, the gaps between drops and strokes, a drop's spread, the idle tempo, the Ebru palette, the ink's mip level) are constants in the builder, tray.py or the shaders, off the page.
- [x] P6 Related parameters are grouped with `startSection`; parameters that don't apply in the current mode are grayed out with `enableExpr`.
  Sections: Inks, Pattern, Drop Size, Comb, Tine Spacing, Hold, Relax and Reset (the tray); Keep Subject, Input 3 Holds, Sensitivity, Depth Type and Max Distance (input 3); Drops and Loudness (the music); then the window. Max Distance grays out unless Depth Type is Distance in Meters. The input-3 and music parameters stay live with nothing wired, as no library effect grays a parameter by its wiring.
- [x] I4 The audio input goes through `audio_in()`, which reads it by channel name with fallbacks and takes a pulse from its count channel when one exists, because a one-frame pulse is lost on any frame nothing pulls the CHOP; the effect reads the counts (`beat_count`, `bar_count`...) for logic, not `beat`. [Cook](https://docs.derivative.ca/Cook), [Logic CHOP](https://docs.derivative.ca/Logic_CHOP)
  Input 2 goes through audio_in(). tray reads beat_count, bar_count and section_count and treats any change in a count as one event (a signal wired in mid-song jumps by every beat so far), never the one-frame beat; level and beat_period it reads as they are. With nothing wired (source 0), idle's count, which goes up every 0.5 s, stands in for the beats, a bar every 4.
- [x] E2 Only capitalized members are promoted; state lives on `self` and the extension can be reinitialized at any time; no module globals; `onInitTD`/`onDestroyTD`, the 2025 names. [Release Notes 2025](https://docs.derivative.ca/Release_Notes/2025.30000)
  No extension in this effect. tray.py keeps its state in a module dict keyed by the operator's id, as lib/audio_callbacks.py does, so nothing of a run is saved into the .tox; Reset starts a fresh state.
- [x] C4 Motion and timing follow seconds (`absTime.seconds`, `me.time.seconds`), not frame counts, so dropped frames don't change the speed. [AbsTime Class](https://docs.derivative.ca/AbsTime_Class)
  Timing is in seconds: each tool's t0, rise, hold and relax are seconds on the shaders' clock (clock_seconds(), wrapped every 16384 s; ages taken modulo it), drops at most every 1/3 s and strokes every 2 s by absTime.seconds, a stroke drawn over one beat_period (0.3 to 1 s), Hold and Relax in bars of 4 beat_periods. The idle beats count absTime.seconds / 0.5. Nothing counts frames.
- [x] C5 Nothing cooks while the output is unused: checked with `dev/idle.py` (nothing downstream, the node out of view; input 2 unwired and wired to a changing beat), or in the Performance Monitor. [Performance Monitor](https://docs.derivative.ca/Performance_Monitor_Dialog)
  dev/idle.py on the final build (node viewer off, nothing downstream): 0 of 202 operators cooked over 60 frames unused, with input 2 unwired and with the clip, its depth and a beat changing every frame wired in; the controls (pulling out_top) cooked 21 and 22.
- [x] C6 Pixel formats are 8-bit unless precision is needed, and 32-bit float for data textures (a CHOP to TOP feeding a shader).
  marble is 8-bit (the picture). ink and clear are 32-bit float: the ring holds each drop's number in alpha to tell a new drop by. near and find are 16-bit float (nearness). The tools reach the shaders as uniform arrays from CHOPs (ta, tb, tc), 32-bit.
- [x] C7 The performance note on the docs page was measured on the reference machine at 1280 x 720, not estimated.
  dev/perf.py, three runs on the Mac otherwise idle (MacBook Pro M2 Pro 16 GB, macOS 15.6, TouchDesigner 2025.33230), 1280 x 720, defaults, the dancer's depth on input 3, the song as raw audio on input 2 (beat=song, so the tray holds what music gives it), the demo paused: GPU 1.74, 1.80, 1.79 ms (95th percentile 3.57, 4.01, 3.69), CPU 0.61, 0.56, 0.61; 60 fps held. marble 0.98 to 1.08 ms. Under the stress beat the tray holds fewer tools (Hold counts its fast bars): GPU 1.08 and 0.89 ms. dev/probes/marbling_full.py, the tray filled for 40 s with the song: Hold 4 held 25 to 27 tools, marble 0.99 ms, the effect's TOPs 2.0 ms; Hold 16 held 52 to 53, marble 5.87 ms, the TOPs 6.38 ms. Before the four samples went into vectors, a full tray took marble 8.3 ms, and before the tools went into uniform arrays (a texture read in the loop) the defaults took 4.3 ms.
- [x] D5 The README DAT and docs page say how to update: dragging a `.tox` in embeds a copy, so updating means dragging in the new one (or pointing External .tox at it). [A word about external files](https://derivative.ca/community-post/word-about-external-files-202310k-builds/68166)
  The README DAT's UPDATING section and the docs page's Use it section both say to delete the copy and drag in the new marbling.tox, or point External .tox at a downloaded file.
- [x] D6 Provenance: the README DAT's CREDITS and the docs page's Credits and license name every paper, technique, project, code, font, model and media the effect uses, follows or was built after, with links and licenses, and call original only what was designed here and has no earlier source after a search. Code recalled from elsewhere that can't be traced is replaced, never called original; code taken from elsewhere is also credited where it sits (a comment in the shader or script). D3 and check_tox.py only see that the sections exist.
  CREDITS and the docs page name Lu, Jaffer, Jin, Zhao and Mao, Mathematical Marbling (IEEE CG&A 2012, read in full: the drop, tine and wavy formulas, the comb's fmod, the per-pixel composition and RGSS), Jaffer's pages (the drop's inverse from Dropping Paint, the nonpareil from the pst-marble How-To, pst-marble's shift), Sims 1992 (as the paper cites it for drawing every tool from scratch), Roberts 2018 (the R2 sequence), the library's depth reading, the beat clock (Dixon 2001, followed) and WCAG 2.3.1. The comb's mean subtraction is the library's, after pst-marble's shift; the bouquet as a comb along a wave is the paper's wavy pattern (its Figure 8), and the page says a marbler's bouquet is drawn otherwise. Not used, with patent numbers: GritWorld US 2023/0106802 and ByteDance US 12,694,597 (carried coordinates or colors), Huawei US 2025/0117558 (docs page), Adobe US 11,409,423 and US 11,755,187. Free versions searched (round 5's research and the docs page): marbling shaders and sketches that make their own inks, none on a picture, no TouchDesigner one. Preview footage credited.
- [x] A2 The flash limits were measured, not assumed: the output recorded with a beat-heavy input at each Flashing setting, and the flashes in any one second counted.
  dev/flash.py + dev/flashcount.py on the final build, worst second by the area rule against the clip alone, stress beat (8 beats, 2 bars, 1 drop a second); no Flashing setting, so one recording each: dancer 1.0 (clip 1.0); flowers 1.0 r1.0 (1.0 r1.0); flowers Ebru 1.0 r1.0; plaza 0.5 (0.5); koi 1.0 r1.5 (0.5 r1.5); corner on the koi (Comb 1, Tine Spacing 0, Drop Size 1) 1.0 r2.0. On the build before the uniform arrays (the same maps), the koi measured 1.0 against 0.5 at 140 BPM (beat=music) and with the song as raw audio too, and the corner on the dancer 1.0 (1.0). The koi's half a flash over the clip is the combs sweeping its orange and white past the dark water, the margin Caustics keeps to (#4796).
- [x] A3 No meaning rests on hue alone (brightness, size or motion carries it too); the palette is colorblind-safe (orange and blue); text is legible at the size it is shown.
  Nothing is signaled by color. Picture's inks are the picture's own colors; Ebru's palette is decorative, its rose short of WCAG's red share (0.66 of R + G + B in linear light against 0.8). No text in the output.
- [x] A4 Anything unreliable is labeled experimental in its help and docs.
  Raw audio's beat clock is labeled experimental in the README DAT (AUDIO, EXPERIMENTAL) and on the docs page (Experimental). Section changes come from Fosfora only and are said so. The rest is deterministic.
