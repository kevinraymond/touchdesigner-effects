# fluid: idiom review

Reviewed version: 0.1.1

The review items of docs/TD_IDIOMS.md, checked by hand for this version: tick each box
(`- [x]`) and say in a few words how it holds.

- [x] P4 Pulse for actions, Toggle for states, Menu for discrete choices; labels in Title Case. Names of 10 characters or fewer are checked at save time (assert_idiomatic); TouchDesigner itself refuses names that aren't an uppercase letter followed by lowercase letters or digits. [Custom Parameters](https://docs.derivative.ca/Custom_Parameters), [Page Class](https://docs.derivative.ca/Page_Class)
  Menus for Look, Emit From, Depth Type and Color (discrete choices), Pulse for Reset (an action), Toggle for Song Moments; Floats for Sensitivity, Max Distance, Amount, Linger, Push, Swirl, Rise, Backdrop, Loudness and Beat Puffs; then the standard Flashing menu, Open Window, Full Screen and Display. Labels in Title Case (Emit From, Depth Type, Max Distance, Beat Puffs, Song Moments); the longest names are Depthtype (9), Emitfrom, Loudness and Backdrop (8), and the build passes the save-time check.
- [x] P5 Inner operators follow the COMP's parameters through expressions (`parent().par.Amount`), not scripts copying values; values only the inside needs are kept off the pages (`ipar`). [Internal Parameters](https://docs.derivative.ca/Internal_Parameters)
  Every inner operator follows the page through expressions: emit's uniforms (Emit From, Sensitivity), near (Depth Type, Max Distance), find (Sensitivity, and whether input 3 is wired), the subject Switch TOP (Emit From), advect (Push, Swirl, Look, Rise, Song Moments, Beat Puffs), dye (Amount, Loudness, Beat Puffs, Linger, Look, Color) and look (Look, Backdrop, Beat Puffs). The one script, reset, pulses the Feedback TOPs' own Reset pulses on Reset (an action, not a copy of a value). Each look's own fade, rise, swirl and flow half-life, the pour rate, the pressure passes, the beat's timing, leap, churn and flare, Depth's Stand Out and Far Limit range and the unwired ball's path stay in the builder; the glow, the speed limit and the motion's thresholds are #defines and numbers in the shaders, off the page.
- [x] P6 Related parameters are grouped with `startSection`; parameters that don't apply in the current mode are grayed out with `enableExpr`.
  Sections: Look and Reset; where it pours (Emit From, Sensitivity, Depth Type, Max Distance, Amount, Linger); how the fluid moves (Push, Swirl, Rise); the look (Color, Backdrop); the music (Loudness, Beat Puffs, Song Moments); then Flashing and the window. Depth Type is grayed out unless Emit From is Depth or Mask, Max Distance unless that and Depth Type is Distance in Meters, Color while Look is Fire (Fire has its own colors). Sensitivity, Linger and Rise apply in every mode, so they stay live.
- [x] I4 The audio input goes through `audio_in()`, which reads it by channel name with fallbacks and takes a pulse from its count channel when one exists, because a one-frame pulse is lost on any frame nothing pulls the CHOP; the effect reads the counts (`beat_count`, `bar_count`...) for logic, not `beat`. [Cook](https://docs.derivative.ca/Cook), [Logic CHOP](https://docs.derivative.ca/Logic_CHOP)
  Input 2 goes through audio_in(). counts selects beat_count and drop_count; a time-sliced Slope CHOP (steps) turns each rise into a one-frame step, ask renames them puff and drop, flash_gate lets them through as often as Flashing allows, and Trigger CHOPs shape them (puff_env, 0.3 s; drop_env, 1 s): envelopes advect, dye and look read every frame, so a step they miss still shows. level and build go through Lag CHOPs. The beat channel is never read.
- [x] E2 Only capitalized members are promoted; state lives on `self` and the extension can be reinitialized at any time; no module globals; `onInitTD`/`onDestroyTD`, the 2025 names. [Release Notes 2025](https://docs.derivative.ca/Release_Notes/2025.30000)
  No extension in this effect, so nothing to promote or reinitialize.
- [x] C4 Motion and timing follow seconds (`absTime.seconds`, `me.time.seconds`), not frame counts, so dropped frames don't change the speed. [AbsTime Class](https://docs.derivative.ca/AbsTime_Class)
  Every step of the simulation goes by absTime.stepSeconds (capped at 0.05 s after a stall): the velocity and the dye are carried by velocity x step, forces add force x step, fades are exp2(-step / half-life in seconds), the pour is a rate per second x step, the motion's drag a rate per second. The input's motion is its optical flow divided by the gap between its new frames in seconds (pace), held between them and dying away after 0.3 s without one, so a 16 fps clip in a 60 fps project pushes as hard as a live camera. Fire's flicker and the unwired ball follow absTime.seconds; the beat's envelopes and the lags are in seconds. No frame counts. 0.1.1: Dye.glsl's clock (the flames' flicker noise) is lib clock_seconds(), wrapped every 16384 s so a 32-bit uniform keeps it to 1 ms (board #4681); lib's pace and speed take the gaps between input frames modulo the wrap, so the motion stays right across it. The flicker's noise jumps once at each wrap (every 4.6 h), within the flicker it already has.
- [x] C5 Nothing cooks while the output is unused: checked with `dev/idle.py` (nothing downstream, the node out of view; input 2 unwired and wired to a changing beat), or in the Performance Monitor. [Performance Monitor](https://docs.derivative.ca/Performance_Monitor_Dialog)
  dev/idle.py on the final 0.1.0 build (node viewer off, nothing downstream): 0 of 110 operators cooked over 60 frames unused, with nothing wired and with the clip, its depth on input 3 and a beat changing every frame wired in; the controls (pulling out_top) cooked 60 and 61. With Emit From on Depth (an earlier build with the same depth chain): 0 of 111, unwired and wired. near and find sit behind the subject Switch TOP and cook only while Emit From is Depth or Mask; the unwired ball and its Over TOP only while nothing is on input 1.
- [x] C6 Pixel formats are 8-bit unless precision is needed, and 32-bit float for data textures (a CHOP to TOP feeding a shader).
  32-bit float for data: the optical flow (lk8, lk4), pace, motion, the velocity at every step (advect, divergence, pressure, velocity) and still, their starting state, and lib's luma (mono32float): speeds, times, pressure and differences of them. 16-bit float for emit, near and find (masks and nearness, where 8 bits would band the comparisons) and for dye, which holds colors times amount and fades by a little each frame (an 8-bit dye would stop fading or band once a frame's fade is under 1/255). The output (look) follows the input's format, 8-bit for video; the ball and its Over TOP are 8-bit. divergence and pressure use one channel of rgba32float, at a quarter of the picture's size.
- [x] C7 The performance note on the docs page was measured on the reference machine at 1280 x 720, not estimated.
  dev/perf.py on the final 0.1.0 build (MacBook Pro M2 Pro 16 GB, macOS 15.6, TouchDesigner 2025.33230), 1280 x 720, the dancer with her depth on input 3, the stress beat, defaults, the demo idle, three runs: GPU 2.80, 2.55 and 2.36 ms (95th percentile 3.83, 3.37, 3.30), CPU 0.60, 0.59, 0.67 ms, 60 fps held; the docs page gives the medians, 2.6 ms (3.4) and 0.6 ms (0.6). Earlier the same night drafts of the same network measured 3.67-4.29 ms GPU (the costliest steps then twice as slow: lk4 1.3 against 0.6-0.8 ms), so the page says GPU times vary by about a third. Steps: pressure 0.76-0.95 ms (40 Jacobi passes at 320 x 180), lk4 0.60-0.82, dye 0.29-0.35, lk8 0.22-0.36. On a draft build: Smoke 3.49 ms against Fire's 3.67-4.29, Ink 4.10, Emit From Depth 3.87 with find 0.27 ms.
- [x] D5 The README DAT and docs page say how to update: dragging a `.tox` in embeds a copy, so updating means dragging in the new one (or pointing External .tox at it). [A word about external files](https://derivative.ca/community-post/word-about-external-files-202310k-builds/68166)
  The README DAT's UPDATING section and the docs page's Use it section both say to delete the copy and drag in the new fluid.tox, or point External .tox at a downloaded file.
- [x] D6 Provenance: the README DAT's CREDITS and the docs page's Credits and license name every paper, technique, project, code, font, model and media the effect uses, follows or was built after, with links and licenses, and call original only what was designed here and has no earlier source after a search. Code recalled from elsewhere that can't be traced is replaced, never called original; code taken from elsewhere is also credited where it sits (a comment in the shader or script). D3 and check_tox.py only see that the sections exist.
  CREDITS and the docs page name stable fluids (Stam 1999) on the GPU as Harris laid it out (GPU Gems ch. 38, 2004), vorticity confinement and buoyancy (Fedkiw, Stam and Jensen 2001), the Beer-Lambert law for the smoke, Lucas-Kanade optical flow (1981) and the clamped Catmull-Rom (1974), both shared with Datamosh, Chris Wellons' lowbias32 hash in the shared helpers (unused here, but in the shader text), TouchDesigner's simplex noise, the depth TOPs' formats, touchFluid, the community TOPs fluid and NVIDIA Flow as read during the survey and not used, the beat clock's tempo induction (Dixon 2001, followed, not copied) and WCAG 2.3.1. The motion held between the input's frames and its drag on the fluid, the looks (the flame palette, the smoke's lighting from its slope) and the beat's leap, churn and glow are written for this library; no search for prior art was made, so none is called original. Tried and dropped, so not credited: a divergence source for the beat's puff (Feldman, O'Brien and Arikan 2003); the builder's comment says why. Shader comments credit Stam, Harris, Fedkiw et al., Lucas and Kanade, Catmull-Rom and Wellons where the code sits.
- [x] A2 The flash limits were measured, not assumed: the output recorded with a beat-heavy input at each Flashing setting, and the flashes in any one second counted.
  Measured with dev/flash.py + dev/flashcount.py on the final build, one run at a time, stress beat of 8 beats, 2 bars and 1 drop a second, 10 s each. Worst second, area rule, Off / Calm / Up to 3 per second (clip alone): dancer, Fire 1.5 / 2.0 / 2.5 (1.0), Smoke 0.5 / 1.0 / 1.5, Ink 0.5 / 2.0 / 1.5; hands, Fire 1.5 / 2.0 / 3.0 (1.5); plaza, Fire 0.5 / 1.0 / 1.0 (0.5); dancer at 140 BPM, Fire 1.0 / 2.0 / 2.5 (1.0). No red flashes; every one within its setting's rule (the hands at Up to 3 per second reach WCAG's 3). Two fixes came from measuring: pure-red flame edges gave 2.5 red flashes a second at Off (the palette now starts at orange, green at least 0.6 of red, since WCAG's red test is in linear light: a dark orange with green at 0.35 still measured 2.0), and every beat puffing gave 2.0 at Off against the clip's 1.0 (the puffs now go through the gate). 0.1.1: not re-measured: only the shader clock changed, wrapped every 16384 s (board #4681), which changes its value, not what the effect does with it, apart from one jump each 4.6 h.
- [x] A3 No meaning rests on hue alone (brightness, size or motion carries it too); the palette is colorblind-safe (orange and blue); text is legible at the size it is shown.
  The fluid takes the picture's colors, one of orange, blue and white, or the flames' palette, as decoration; nothing is signaled by hue, and hotter flames are brighter as well as yellower. The flames never turn red (see A2). No text.
- [x] A4 Anything unreliable is labeled experimental in its help and docs.
  Fosfora's drop detection is marked experimental in the Song Moments help, the README DAT and the docs page; raw-audio beats (a kick detector and a beat clock) in the README DAT and the docs page; the cut heuristic in the README DAT's EXPERIMENTAL section and the docs page's Experimental section. Each Emit From mode's limits (Movement: still people stop, moving shadows, a moving camera; Depth: people cut off at the sides, feet) are in the README DAT and the docs page.
