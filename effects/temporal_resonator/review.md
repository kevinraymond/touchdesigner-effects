# temporal_resonator: idiom review

Reviewed version: 0.1.1

The review items of docs/TD_IDIOMS.md, checked by hand for this version: tick each box
(`- [x]`) and say in a few words how it holds.

- [x] P4 Pulse for actions, Toggle for states, Menu for discrete choices; labels in Title Case. Names of 10 characters or fewer are checked at save time (assert_idiomatic); TouchDesigner itself refuses names that aren't an uppercase letter followed by lowercase letters or digits. [Custom Parameters](https://docs.derivative.ca/Custom_Parameters), [Page Class](https://docs.derivative.ca/Page_Class)
  Menus for Mode, Length, Plucks and Depth Type (discrete choices); Floats for Sustain, Strength, Softness, Threshold, Tempo, Loudness and Max Distance; an Int for Display; a Toggle for Full Screen (a state); Pulses for Open Window and Open Docs. Labels in Title Case (Max Distance, Depth Type, Open Window). Plucks' name is Pluck and Max Distance's Maxdist; the longest names are Fullscreen and Openwindow (10).
- [x] P5 Inner operators follow the COMP's parameters through expressions (`parent().par.Amount`), not scripts copying values; values only the inside needs are kept off the pages (`ipar`). [Internal Parameters](https://docs.derivative.ca/Internal_Parameters)
  Every inner operator follows the page through expressions: beat reads Tempo (with nothing on input 2) and folds the beat; delay_to reads Length; pluck reads Plucks and Loudness (through level_smooth); stamp, taps and string read the delay (op('delay')), Softness (the spread in time and across the picture), Mode, Sustain and Length (the loop's gain) and Threshold; near reads Depth Type and Max Distance; show reads Strength; states and stamps size their rings from Length and the project's cook rate. Values only the inside needs (the beat's range, the glide, the pluck's attack and floor, Always' strength, the spread and blur at Softness 1, the background's step, the pause that restarts the strings, the depth limits) are constants in the builder, off the page.
- [x] P6 Related parameters are grouped with `startSection`; parameters that don't apply in the current mode are grayed out with `enableExpr`.
  Sections: Mode, Length, Sustain, Strength, Softness and Threshold (the strings); Plucks, Tempo and Loudness (when and how hard they are plucked); Depth Type and Max Distance (input 3); then the window. Max Distance grays out unless Depth Type is Distance in Meters. Tempo stays live with input 2 wired, as no library effect grays a parameter by its wiring; its help says it is the beat with nothing on input 2. Everything else applies in every mode.
- [x] I4 The audio input goes through `audio_in()`, which reads it by channel name with fallbacks and takes a pulse from its count channel when one exists, because a one-frame pulse is lost on any frame nothing pulls the CHOP; the effect reads the counts (`beat_count`, `bar_count`...) for logic, not `beat`. [Cook](https://docs.derivative.ca/Cook), [Logic CHOP](https://docs.derivative.ca/Logic_CHOP)
  Input 2 goes through audio_in(). beat reads beat_period, the new channel (Fosfora's bpm, raw audio's beat clock, else the gaps between beats), and source; phase reads beat_phase; level_pick selects level and level_smooth (a Filter CHOP, 0.5 s) eases it for pluck. No logic counts beats here: plucks follow the beat's phase, so a missed pulse can't drop one, and the one-frame beat channel is never read. With nothing wired, source is 0: the beat is Tempo's, its phase from absTime.seconds, and the loudness doesn't count.
- [x] E2 Only capitalized members are promoted; state lives on `self` and the extension can be reinitialized at any time; no module globals; `onInitTD`/`onDestroyTD`, the 2025 names. [Release Notes 2025](https://docs.derivative.ca/Release_Notes/2025.30000)
  No extension in this effect, so nothing to promote or reinitialize.
- [x] C4 Motion and timing follow seconds (`absTime.seconds`, `me.time.seconds`), not frame counts, so dropped frames don't change the speed. [AbsTime Class](https://docs.derivative.ca/AbsTime_Class)
  Everything is in seconds. The delay is the beat's length in seconds, gliding at most 0.25 s a second (a Lag CHOP); taps find the slots by each slot's stamped time, so a dropped frame changes which slots, not when the echoes land, and a pause longer than 0.5 s (the output unused) starts the strings again rather than replaying stale ones. The background steps toward the picture by 0.6 a second times the time since the last cook. Plucks follow the beat's phase; without input 2 the phase is absTime.seconds times Tempo / 60, wrapped to 0-1 in Python. Shaders get the time as clock_seconds().
- [x] C5 Nothing cooks while the output is unused: checked with `dev/idle.py` (nothing downstream, the node out of view; input 2 unwired and wired to a changing beat), or in the Performance Monitor. [Performance Monitor](https://docs.derivative.ca/Performance_Monitor_Dialog)
  dev/idle.py on the final build (node viewer off, nothing downstream): 0 of 233 operators cooked over 60 frames unused, with input 2 unwired and with the clip, its depth and a beat changing every frame wired in; the controls (pulling out_top) cooked 42 and 45. The rings write only while something pulls them, and the stamps tell a pause from history, so nothing of a pause is replayed. 0.1.1: lib optical_flow(flow=False) leaves out the optical flow (lk8) and lum8p, which only lk8 read. They never cooked: dev/probes/flow_cooks.py pulled the 0.1.0 output with the clip, its depth and the stress beat for 120 frames, and they cooked 0 times. dev/idle.py on the 0.1.1 build found 0 of 229 operators cooked over 60 frames unused, unwired and wired; the controls cooked 42 and 45.
- [x] C6 Pixel formats are 8-bit unless precision is needed, and 32-bit float for data textures (a CHOP to TOP feeding a shader).
  background, string (both buffers) and the states ring are 16-bit float: the strings carry signed differences that ring down over many trips, which 8 bits would round to a stop (a step under 1/255 never decays) and can't hold below 0. stamp, the stamps ring and taps are 32-bit float data (serials, times on the wrapped clock, slots); near and find are 16-bit float (nearness 0-1). show is 8-bit, the picture. The lib clock's passes keep their reviewed formats. 0.1.1: the flow pass (lk8) and lum8p are gone; the rest keep their formats.
- [x] C7 The performance note on the docs page was measured on the reference machine at 1280 x 720, not estimated.
  dev/perf.py, three runs with /tdlib_demo paused (dev/probes/demo_pause.py; MacBook Pro M2 Pro 16 GB, macOS 15.6, TouchDesigner 2025.33230), 1280 x 720, defaults, the dancer's depth on input 3, stress beat: GPU 1.60, 1.59, 1.59 ms (95th percentile 1.75, 1.75, 1.76), CPU 0.44, 0.44, 0.43 ms, 60 fps held each time; the page gives 1.6 ms (1.75) and 0.44 ms. Costliest: echo 0.32 (string's second buffer), string 0.25, find 0.22, clock 0.15, states 0.15, near 0.14, taps 0.13. find at a quarter size cost 0.45 ms and the whole 2.3 ms, so near and find run at an eighth. Without input 3 (an earlier build): 1.25 ms. GPU memory by TOP.gpuMemory (dev/probes/resonator_memory.py): 161 MB at 1 Beat, 100 at 1/2, 285 at 2. 0.1.1: not re-measured. The passes left out never cooked (C5), so each frame does the same work.
- [x] D5 The README DAT and docs page say how to update: dragging a `.tox` in embeds a copy, so updating means dragging in the new one (or pointing External .tox at it). [A word about external files](https://derivative.ca/community-post/word-about-external-files-202310k-builds/68166)
  The README DAT's UPDATING section and the docs page's Use it section both say to delete the copy and drag in the new temporal_resonator.tox, or point External .tox at a downloaded file.

Original, after a search: the strings as the picture's difference from its background, plucked on the beat and tuned to the tempo, the echoes behind what stands out now (and in front of nothing input 3 finds in front), the delay line in a ring of stamped slots read through a Feedback TOP.

- [x] A3 No meaning rests on hue alone (brightness, size or motion carries it too); the palette is colorblind-safe (orange and blue); text is legible at the size it is shown.
  Nothing is signaled by color: the echoes keep the picture's own colors (through the red guard), and Alternating's shadows are told by brightness, darker against what's behind them. No text in the output.
- [x] A4 Anything unreliable is labeled experimental in its help and docs.
  The cut that starts the strings again is a heuristic (lib clock.glsl's), labeled experimental in the README DAT and on the docs page. The rest is deterministic: the tempo from the audio input, which labels its own guesses (Fosfora's drops, the bands' stand-ins) where it describes them.
