# glitch: idiom review

Reviewed version: 0.1.2

The review items of docs/TD_IDIOMS.md, checked by hand for this version: tick each box
(`- [x]`) and say in a few words how it holds.

- [x] P4 Pulse for actions, Toggle for states, Menu for discrete choices; labels in Title Case. Names of 10 characters or fewer are checked at save time (assert_idiomatic); TouchDesigner itself refuses names that aren't an uppercase letter followed by lowercase letters or digits. [Custom Parameters](https://docs.derivative.ca/Custom_Parameters), [Page Class](https://docs.derivative.ca/Page_Class)
  Menus for Bursts and Flashing (discrete choices); Toggles for Blocks, Tears, Song Moments and Full Screen; Floats for Amount, Length and RGB Split, Int for Block Size and Display; Pulses for Open Window and Open Docs. Labels in Title Case; the longest name is Blocksize (9), and the build passes the save-time check.
- [x] P5 Inner operators follow the COMP's parameters through expressions (`parent().par.Amount`), not scripts copying values; values only the inside needs are kept off the pages (`ipar`). [Internal Parameters](https://docs.derivative.ca/Internal_Parameters)
  Every inner operator follows the page through expressions: the GLSL uniforms (parent().par.Amount, Blocksize, Split, Blocks, Tears, Moments), the burst requests' gains (Bursts, Moments), the burst's hold (Length) and the gate and budget (Flashing). No script copies values. The steady period, the flash spacing and the tear and block odds stay in the builder and shader, off the page.
- [x] P6 Related parameters are grouped with `startSection`; parameters that don't apply in the current mode are grayed out with `enableExpr`.
  Sections: Bursts to Block Size (when and how much), Blocks to Song Moments (what a burst does), then Flashing, then the window. Nothing on the page is mode-specific, so nothing needs graying out.
- [x] I4 The audio input goes through `audio_in()`, which reads it by channel name with fallbacks and takes a pulse from its count channel when one exists, because a one-frame pulse is lost on any frame nothing pulls the CHOP; the effect reads the counts (`beat_count`, `bar_count`...) for logic, not `beat`. [Cook](https://docs.derivative.ca/Cook), [Logic CHOP](https://docs.derivative.ca/Logic_CHOP)
  Input 2 goes through audio_in(). counts selects beat_count, bar_count and drop_count; a time-sliced Slope CHOP (steps) turns each rise into a one-frame step. Beat steps drive the small glitches (beat_env, and beat_n seeds them); the burst requests follow bars (or beats) and drops, and the burst's own number (burst_count) seeds its damage. The beat channel is never read. 0.1.1 changes only lib/audio_callbacks.py (#4652): raw audio's beats now come from a beat clock locked to the kicks' tempo (bars every 4 of its beats), and Fosfora's level from its bass. Its logic is unchanged here. Checked by dev/selftest.py (every input kind, Fosfora's level from bass) and dev/beat_bench.py --selftest.
- [x] E2 Only capitalized members are promoted; state lives on `self` and the extension can be reinitialized at any time; no module globals; `onInitTD`/`onDestroyTD`, the 2025 names. [Release Notes 2025](https://docs.derivative.ca/Release_Notes/2025.30000)
  No extension in this effect, so nothing to promote or reinitialize.
- [x] C4 Motion and timing follow seconds (`absTime.seconds`, `me.time.seconds`), not frame counts, so dropped frames don't change the speed. [AbsTime Class](https://docs.derivative.ca/AbsTime_Class)
  Everything is in seconds: the steady clock (absTime.seconds), the beat glitches' envelope (a 0.3 s Trigger CHOP decay), the burst's hold (Length), the gate and budget (re-trigger delays in seconds) and the drop's fade. dev/probes/effect_beats.py with the song: bursts 1.2 to 1.3 s apart at Calm while beats came every 0.43 s. Nothing counts frames.
- [x] C5 Nothing cooks while the output is unused: checked with `dev/idle.py` (nothing downstream, the node out of view; input 2 unwired and wired to a changing beat), or in the Performance Monitor. [Performance Monitor](https://docs.derivative.ca/Performance_Monitor_Dialog)
  dev/idle.py on the final 0.1.0 build (node viewer off, nothing downstream): 0 of 46 operators cooked over 60 frames unused, with input 2 unwired and with the clip and a beat changing every frame wired in; the control (pulling out_top) cooked 36 and 37. dev/idle.py on the 0.1.1 build: 0 of 46 operators cooked over 60 frames unused, unwired and wired; control 36 and 37. dev/idle.py on the 0.1.2 build: 0 of 236 operators (the Network Boxes' insides included) cooked over 60 frames unused, unwired and wired; control 36 and 37.
- [x] C6 Pixel formats are 8-bit unless precision is needed, and 32-bit float for data textures (a CHOP to TOP feeding a shader).
  8-bit for the pictures (hold and glitch); no data textures.
- [x] C7 The performance note on the docs page was measured on the reference machine at 1280 x 720, not estimated.
  dev/perf.py on the final 0.1.0 build (MacBook Pro M2 Pro 16 GB, macOS 15.6, TouchDesigner 2025.33230), 1280 x 720, defaults: GPU 0.24 ms (95th percentile 0.41), CPU 0.28 ms (0.36), 60 fps held, with the Mac awake (a locked display throttles TouchDesigner to 1 fps). dev/perf.py on the 0.1.1 build, demo paused (2026-10-24): GPU 0.18 ms (95th percentile 0.30), CPU 0.30 ms (0.34), 60 fps held. The change is Python in the audio input's Script CHOP (CPU, once a cook); GPU times on this Mac swing about a third between runs with the GPU's clock (Datamosh 2.8 to 4.0 ms on one build), so the docs page keeps the published numbers. 0.1.2 only lays the network out (Network Boxes, positions), drops the unused compute shaders and holds the README to one line per paragraph: dev/probes/structure_diff.py against 0.1.1 finds every other operator, parameter, expression and wire unchanged, so these numbers stand.
- [x] D5 The README DAT and docs page say how to update: dragging a `.tox` in embeds a copy, so updating means dragging in the new one (or pointing External .tox at it). [A word about external files](https://derivative.ca/community-post/word-about-external-files-202310k-builds/68166)
  The README DAT's UPDATING section and the docs page's Use it section both say to delete the copy and drag in the new glitch.tox, or point External .tox at a downloaded file.
- [x] D6 Provenance: the README DAT's CREDITS and the docs page's Credits and license name every paper, technique, project, code, font, model and media the effect uses, follows or was built after, with links and licenses, and call original only what was designed here and has no earlier source after a search. Code recalled from elsewhere that can't be traced is replaced, never called original; code taken from elsewhere is also credited where it sits (a comment in the shader or script). D3 and check_tox.py only see that the sections exist.
  CREDITS and the docs page name glitch art's vocabulary of damage, lowbias32 (public domain), the surveyed but unused glitch components and WCAG 2.3.1; the bursts and the flash budget are written for this library. A scan of the shader for known hashes and formulas found only lowbias32. The beat clock's tempo from the gaps between kicks is credited in both as inter-onset-interval tempo induction, the idea behind Dixon 2001, followed, not copied.
- [x] A2 The flash limits were measured, not assumed: the output recorded with a beat-heavy input at each Flashing setting, and the flashes in any one second counted.
  dev/flash.py + dev/flashcount.py on the final 0.1.0 build, stress beat of 8 beats, 2 bars and 1 drop a second, 600 frames each. Worst second, area rule: dancer Off 1.0, Calm 1.5, Up to 3 per second 2.0 (clip alone 1.0); plaza 0.5, 1.0, 1.5 (clip 0.5); dancer with no beat (steady glitches) 1.0 at every setting (clip 1.0). Red flashes: Calm 0.5, Up to 3 per second 1.0 on the dancer, 0, 1.0 on the plaza, none at Off or with no beat (the split's kick). The glitches on every beat (8 a second here) register as no flashes. All within flashcount's bars. Re-measured on 0.1.1 (same stress beat): dancer Off 1.0, Calm 1.5, Up to 3 per second 2.0 (clip 1.0); plaza 0.5, 1.0, 1.5 (clip 0.5); red 1.0 at most; and with a 140 BPM beat (dev/testbed.py beat=music) 1.0, 1.0, 1.5 on the dancer. Unchanged from 0.1.0. 0.1.2 only lays the network out (Network Boxes, positions), drops the unused compute shaders and holds the README to one line per paragraph: dev/probes/structure_diff.py against 0.1.1 finds every other operator, parameter, expression and wire unchanged, so these numbers stand.
- [x] A3 No meaning rests on hue alone (brightness, size or motion carries it too); the palette is colorblind-safe (orange and blue); text is legible at the size it is shown.
  Nothing is signaled by color: the RGB split and crushed colors are decoration, and the bursts carry their timing by their whole-picture change. No text is drawn.
- [x] A4 Anything unreliable is labeled experimental in its help and docs.
  Fosfora's drop detection is marked experimental in the Song Moments help, the README DAT and the docs page; raw-audio beat detection is marked experimental in the README DAT and the docs page. The wording now says raw-audio beats come from a kick detector and a beat clock that locks to the kicks' tempo, experimental: it can still add or miss beats and which beat starts a bar is a guess.
