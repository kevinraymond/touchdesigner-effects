# showreel: idiom review

Reviewed version: 0.1.3

The review items of docs/TD_IDIOMS.md, checked by hand for this version: tick each box
(`- [x]`) and say in a few words how it holds.

- [x] P4 Pulse for actions, Toggle for states, Menu for discrete choices; labels in Title Case. Names of 10 characters or fewer are checked at save time (assert_idiomatic); TouchDesigner itself refuses names that aren't an uppercase letter followed by lowercase letters or digits. [Custom Parameters](https://docs.derivative.ca/Custom_Parameters), [Page Class](https://docs.derivative.ca/Page_Class)
  Menu for View (discrete choices) and Flashing; Toggle for Labels and Full Screen; Int for Every and Display; Pulses for Open Window and Open Docs. Labels in Title Case; names are 10 characters or fewer (save-time check passes). The effects inside keep their own reviewed pages. 0.1.3 adds Fluid inside (its own page of parameters, reviewed in effects/fluid/review.md); the showreel's page is unchanged.
- [x] P5 Inner operators follow the COMP's parameters through expressions (`parent().par.Amount`), not scripts copying values; values only the inside needs are kept off the pages (`ipar`). [Internal Parameters](https://docs.derivative.ca/Internal_Parameters)
  The page drives the inside through expressions: view's index (parent().par.View, Every through the cycle CHOP's step and fade), label's uniforms (parent().par.Labels), and every embedded effect's Flashing (parent().par.Flashing). No script copies values. The names, the 2 s bar, the 2 s minimum gap and the 1 s fade live in the builder and src/, off the page. 0.1.3: unchanged; Fluid's Flashing follows the showreel's like the others'.
- [x] P6 Related parameters are grouped with `startSection`; parameters that don't apply in the current mode are grayed out with `enableExpr`.
  Sections: View, Every and Labels; then Flashing; then the window. Every is grayed out unless View is Cycle (enableExpr); Labels applies to every view. 0.1.3: unchanged.
- [x] I4 The audio input goes through `audio_in()`, which reads it by channel name with fallbacks and takes a pulse from its count channel when one exists, because a one-frame pulse is lost on any frame nothing pulls the CHOP; the effect reads the counts (`beat_count`, `bar_count`...) for logic, not `beat`. [Cook](https://docs.derivative.ca/Cook), [Logic CHOP](https://docs.derivative.ca/Logic_CHOP)
  Input 2 reaches each embedded effect unchanged (each goes through its own audio_in()); the showreel's own audio_in() feeds only cycle, which reads the bar_count and source channels, never the one-frame beat pulse. 0.1.1: the effects inside and the showreel's own audio_in() take raw audio's beats from the beat clock (lib/audio_callbacks.py, #4652), so Cycle's bars on raw audio come every 4 locked beats. 0.1.3: Fluid reads input 2 through its own audio_in() too (beat_count and drop_count through its flash gate).
- [x] E2 Only capitalized members are promoted; state lives on `self` and the extension can be reinitialized at any time; no module globals; `onInitTD`/`onDestroyTD`, the 2025 names. [Release Notes 2025](https://docs.derivative.ca/Release_Notes/2025.30000)
  No extension in the showreel; the effects inside have none either. 0.1.3: Fluid has none either.
- [x] C4 Motion and timing follow seconds (`absTime.seconds`, `me.time.seconds`), not frame counts, so dropped frames don't change the speed. [AbsTime Class](https://docs.derivative.ca/AbsTime_Class)
  Cycle's timing is in seconds: src/cycle.py reads absTime.seconds for the 2 s bar without music, the 2 s minimum gap and the 1 s fade, and counts input 2's bars; dev/probes/showreel_cycle.py measured moves exactly 2.0 s apart with nothing wired and under a 2-bars-a-second beat at Every 1. Nothing counts frames. 0.1.3: unchanged; Fluid steps its simulation by absTime.stepSeconds (its review, C4).
- [x] C5 Nothing cooks while the output is unused: checked with `dev/idle.py` (nothing downstream, the node out of view; input 2 unwired and wired to a changing beat), or in the Performance Monitor. [Performance Monitor](https://docs.derivative.ca/Performance_Monitor_Dialog)
  dev/idle.py on the 0.1.0 build with ascii, blob_track, datamosh, glitch, particles and point_cloud inside and the dancer's depth carried with her clip (node viewer off, nothing downstream): 0 of 513 operators cooked over 60 frames unused, with nothing wired and with the clip, its depth on input 3 and a changing beat wired in; the control cooked 56 and 58. The cycle CHOP and its clock cook only while View is Cycle (the view reads them only then); the blending Switch TOP cooks only the inputs it shows, one effect, or two during a fade (dev/probes/showreel_fade.py logged which cooked every frame); the two built-in clips show the frame the clock picks, which costs nothing while nothing pulls them. dev/idle.py on the 0.1.1 build (ascii 0.2.0, blob_track 0.1.2, datamosh 0.2.0, glitch 0.1.1, particles 0.3.0, point_cloud 0.1.1 inside): 0 of 531 operators cooked over 60 frames unused, unwired and wired; control 57 and 59. dev/idle.py on the 0.1.2 build (Particles 0.3.1, Point Cloud 0.1.2 and the new dancer depth inside): 0 of 531 operators cooked over 60 frames unused, unwired and wired; control 57 and 59. dev/idle.py on the 0.1.3 build (Fluid 0.1.0 added; every effect rebuilt for the lib change): 0 of 643 operators cooked over 60 frames unused, unwired and wired; control 57 and 59.
- [x] C6 Pixel formats are 8-bit unless precision is needed, and 32-bit float for data textures (a CHOP to TOP feeding a shader).
  view and label are 8-bit (the pictures); the Null TOPs pass each effect's own format; no data textures of its own (the effects inside keep their reviewed formats). 0.1.3: unchanged; Fluid keeps its reviewed formats.
- [x] C7 The performance note on the docs page was measured on the reference machine at 1280 x 720, not estimated.
  dev/perf.py on the 0.1.0 build with ascii, blob_track, datamosh, glitch, particles and point_cloud inside (MacBook Pro M2 Pro 16 GB, macOS 15.6, TouchDesigner 2025.33230), 1280 x 720, the dancer with its depth on input 3, the demo paused: Cycle (default) GPU 3.74 ms (95th percentile 8.55, two effects during a fade), CPU 1.39 ms (2.03); 60 fps held. Grid is gone: with six effects it took 9.95 ms GPU and grew with every effect. Remeasured whenever the effects inside change. dev/perf.py on the 0.1.1 build, the demo paused: Cycle GPU 3.69 ms (95th percentile 9.13, two effects during a fade), CPU 1.35 ms (1.92); 60 fps held. dev/perf.py on the 0.1.2 build, three runs, the demo paused: Cycle GPU 4.35, 4.23 and 3.05 ms (95th percentile 7.37, 7.45, 5.88), CPU 1.12, 1.66, 1.13 ms, 59-60 fps; the docs page now gives the medians, 4.2 ms (7.4) and 1.1 ms (1.6). dev/perf.py on the 0.1.3 build (seven effects inside), three runs, the demo idle: Cycle GPU 4.10, 4.05 and 4.08 ms (95th percentile 8.02, 7.89, 7.10), CPU 1.53, 1.48, 1.19 ms, 59 fps; the docs page gives the medians, 4.1 ms (7.9) and 1.5 ms (1.7). One effect runs at a time, so adding Fluid didn't add its cost.
- [x] D5 The README DAT and docs page say how to update: dragging a `.tox` in embeds a copy, so updating means dragging in the new one (or pointing External .tox at it). [A word about external files](https://derivative.ca/community-post/word-about-external-files-202310k-builds/68166)
  The README DAT's UPDATING section and the docs page's Use it section say to delete the copy and drag in the new showreel.tox; both say a new effect in the library means a new showreel. 0.1.3: unchanged.
- [x] D6 Provenance: the README DAT's CREDITS and the docs page's Credits and license name every paper, technique, project, code, font, model and media the effect uses, follows or was built after, with links and licenses, and call original only what was designed here and has no earlier source after a search. Code recalled from elsewhere that can't be traced is replaced, never called original; code taken from elsewhere is also credited where it sits (a comment in the shader or script). D3 and check_tox.py only see that the sections exist.
  CREDITS and the docs page credit the effects inside to their own pages, the built-in dancer clip (Kevin Raymond, CC BY 4.0, AI-generated with Krea 2 and Wan 2.2) and her depth (Depth Anything 3 Base, Apache 2.0), the 5 x 7 font and WCAG 2.3.1. 0.1.1: the beat clock (Cycle's bars on raw audio) is credited in both as inter-onset-interval tempo induction, the idea behind Dixon 2001, followed, not copied. 0.1.2: her depth is now Depth Anything 3's Mono-Large model (Apache 2.0), one frame at a time, held steady from frame to frame by a scale fit written for this library; credited so in both. 0.1.3: Fluid is credited on its own page like the others; the docs page's preview (the README's hero) now includes Fluid's take, recorded like the rest (b1_dancer, m1x_ease_from_drop, 8 s).
- [x] A2 The flash limits were measured, not assumed: the output recorded with a beat-heavy input at each Flashing setting, and the flashes in any one second counted.
  dev/flash.py + dev/flashcount.py on the 0.1.0 build with the six effects inside (particles and point_cloud getting the dancer's depth, Depth Anything 3 Base, on input 3, showing the clip's frame), one run at a time, stress beat of 8 beats, 2 bars and 1 drop a second (Cycle then moves every 2 s, the fastest it allows). Cycle's cut, before the fade, reached 3.5 at Up to 3 per second with six effects (FAIL); the 1 s fade fixed it. No red flashes. All within flashcount's bars. 0.1.1 (Datamosh's bloom and Particles' sparks gated, both new): Cycle on the dancer Off 1.0, Calm 2.0, Up to 3 per second 2.5 (clip 1.0); plaza 0.5, 1.5, 3.0 (clip 0.5); Every 1 on the dancer 1.0, 2.0, 2.5. No red flashes; each within its setting's rule. 0.1.2 (the new dancer depth, Particles 0.3.1, Point Cloud 0.1.2): Cycle on the dancer Off 1.0, Calm 2.0, Up to 3 per second 3.0 (clip 1.0), within WCAG's 3 as 0.1.0 was; the plaza carries no depth, so its numbers stand. 0.1.3 (Fluid added): Cycle on the dancer Off 1.0, Calm 2.0, Up to 3 per second 3.0 (clip 1.0), red 0.5 at Up to 3 per second (Glitch's color split, which measures 1.0 red on its own, happened to show in the 10 s; under WCAG's 3); plaza 0.5, 1.5, 2.5 (clip 0.5); Every 1 on the dancer 1.0, 2.0, 2.5. - [x] A3 No meaning rests on hue alone (brightness, size or motion carries it too); the palette is colorblind-safe (orange and blue); text is legible at the size it is shown.
